# Сверка с материалами курса

Сверка выполнена 8 октября 2026 года по четырём DOCX и трём PPTX, предоставленным
пользователем из папки Downloads. Цель проекта — космический календарь на Go.
Пример службы доставки применяется как архитектурный образец: заказы заменены
событиями, обработка заказа — подготовкой события. Тема календаря сохраняется.

## Обязательные лабораторные работы

Источник — «Лабораторные работы и задания проекта.docx», раздел пяти лабораторных.

| Пункт | Реализация | Проверка |
|---|---|---|
| ЛР1 HTTP Go и GET `/test` с `Hello!` | `internal/transport/http.go`, `usecase.Service.Test`, `repository.Test` | Smoke получает точную строку; unit подтверждает вызов репозитория |
| ЛР1 три изолированных слоя | `usecase.Calendar`, `usecase.Repository`, адаптеры | Интерфейсы проверяет компилятор; схемы в architecture.md |
| ЛР1 graceful shutdown | `internal/runtime/server.go` | Тест удерживает запрос во время остановки и проверяет полный ответ |
| ЛР2 PostgreSQL и таблицы | `internal/repository/postgres.go`, `schema.sql` | Реальный PostgreSQL в Compose и отдельная БД тестов |
| ЛР2 POST `/dbtest` | Защищённый POST сохраняет строку и владельца | Smoke и наличие строки в `database_probes` |
| ЛР3 регистрация и JWT | Register/Login, bcrypt, `security.Tokens` | Неверный пароль, повторный email, поддельный и истёкший JWT |
| ЛР4 создать объект и просмотреть статусы своих объектов | POST/GET `/api/events`, `processingStatus` | Полный API-цикл и возвращение `ready` через RabbitMQ |
| ЛР5 middleware и ID пользователя | JWT и сессия проверяются, identity передаётся в контекст | Два аккаунта; чужие GET/PUT/DELETE/export недоступны |

ЛР2-тестовый маршрут требует входа, чтобы не делать запись в БД доступной без
аккаунта. В PostgreSQL он действительно пишет в БД; в локальном JSON-просмотре
реализует тот же интерфейс файловым адаптером.

## Расширенные уровни

Источник — шкала в начале того же DOCX и презентации для продвинутых, часть 1,
раздел архитектуры и инфраструктуры, часть 2, разделы RabbitMQ и Worker Pool.

| Уровень | Реализация | Проверка |
|---|---|---|
| 6–7 отдельный обработчик | `cmd/worker`, `usecase.EventWorker` | Самостоятельный контейнер с четырьмя воркерами |
| 6–7 брокер в обе стороны | Очереди `orbita.events.new` и `orbita.events.status` | Событие pending становится ready через обработчик |
| 8 Docker Compose | API, worker, PostgreSQL, RabbitMQ, Prometheus, Grafana | Сборка и запуск всех сервисов |
| 8 наблюдаемость | JSON-логи, Prometheus, provisioning Grafana | Три scrape-цели доступны; восемь панелей загружены |
| 9–10 сервис нагрузки | `cmd/loadgen`, профиль `load` | 20 пользователей, 599 запросов за 30 секунд, 0 ошибок |

Дополнительно сохранение события и outbox выполняется в одной транзакции,
публикация использует подтверждения, доставка — ручные ACK. Проверены аренда
сообщений, повторное применение статуса и защита ревизии от устаревшего статуса.

## Остальные предоставленные файлы

«Документация чистой архитектуры демонстрационного сервиса.docx» описывает
изоляцию бизнес-логики и адаптеров, интерфейсы и заменяемость хранилища. Это
реализовано разделением пакетов и PostgreSQL/JSON-адаптерами одного интерфейса.
«Методические материалы для начинающих.docx» и презентация для начинающих —
учебные пояснения синтаксиса, модулей, структур, интерфейсов и конкурентности.
В проекте используются Go Modules с `go.sum`, gofmt, контексты, каналы, мьютекс
для файла и ограниченный пул обработчиков.

«Кейсовые задания.docx» содержит отдельные упражнения уровней A и B по Go.
Назначенный номер или набор упражнений пользователь не указал; эти упражнения
не добавляются как функции календаря и не отмечаются выполненными отдельно.

## Границы трактовки

Презентации показывают пример доставки еды и конкретные библиотеки. В календаре
сохраняются сценарии и границы слоёв, но SQL-драйвер — pgx, HTTP — стандартный
`net/http`. Сессия хранится в БД и отзывается при выходе; её срок фиксирован и
не превышает срок JWT. Автоматическое продление сессии без перевыпуска JWT из
учебного примера не используется. Метрики показываются в Grafana; текстовые
JSON-логи остаются в stdout контейнеров. Отдельная система хранения логов не добавлена.

Результаты соответствуют выполненным локальным проверкам, приведённым в
verification.md. Итоговую учебную оценку определяет преподаватель; отдельный
набор кейсовых упражнений или требование к форме отчёта в запросе не назначены.
